About Disaster Recovery

Disaster recovery helps the facility restore important IT systems after a failure or emergency. The main goal is to reduce downtime and protect research information.

Available Recovery Plans

  • Network Failure
  • Server Failure
  • Cybersecurity Incident
  • Power Failure
  • Fibre Link Failure
  • Fire or Flood
  • Data Loss
  • DHCP/DNS Failure

1. Network Failure

Responsible: Network and Systems Administrator

  1. Identify which part of the network is not working.
  2. Check switches, routers and network cables.
  3. Check device power and network settings.
  4. Repair or replace faulty equipment.
  5. Restore saved configurations if required.
  6. Test connectivity between VLANs and buildings.
  7. Record the problem and solution.

2. Server Failure

Responsible: Network and Systems Administrator

  1. Identify the cause of the server failure.
  2. Check server hardware and operating system.
  3. Repair or replace faulty components.
  4. Restore services using verified backups if necessary.
  5. Test the central server and research applications.
  6. Record the recovery actions.

3. Cybersecurity Incident

Responsible: Cybersecurity Officer

  1. Report the incident immediately.
  2. Identify affected systems.
  3. Isolate infected computers where appropriate.
  4. Preserve relevant logs and evidence.
  5. Investigate the cause of the incident.
  6. Remove malware or rebuild affected systems.
  7. Restore clean backups if needed.
  8. Test security before reconnecting devices.

4. Power Failure

Responsible: IT Manager and Systems Administrator

  1. Identify the affected buildings and devices.
  2. Check available UPS equipment.
  3. Shut down important systems safely if required.
  4. Contact facilities personnel about the outage.
  5. Wait for stable power to be restored.
  6. Restart servers and network devices safely.
  7. Test all important IT services.

5. Fibre Link Failure

Responsible: Network Technician

  1. Identify which building has lost connectivity.
  2. Check the fibre connection and network ports.
  3. Inspect transceivers and network equipment.
  4. Use an approved alternative connection if available.
  5. Arrange repair or replacement of damaged fibre.
  6. Test communication between buildings.
  7. Update network maintenance records.

6. Fire, Flood or Physical Disaster

Responsible: IT Manager and Facility Management

  1. Follow emergency procedures and evacuate staff.
  2. Contact emergency services.
  3. Do not enter unsafe areas.
  4. Assess damage when the area is declared safe.
  5. Identify equipment that can be recovered.
  6. Arrange an approved alternative location if necessary.
  7. Restore critical systems and data from available backups.
  8. Test restored services before normal operations resume.

7. Data Loss or Corruption

Responsible: Network and Systems Administrator

  1. Identify the missing or damaged information.
  2. Investigate the cause of the data loss.
  3. Prevent further changes to affected data where necessary.
  4. Find the latest suitable verified backup.
  5. Restore the information securely.
  6. Check that recovered files are correct.
  7. Confirm that authorised users can access the files.
  8. Record the incident and recovery results.

8. DHCP/DNS Failure

Responsible: Network and Systems Administrator

  1. Check whether the central server is running.
  2. Check the DHCP and DNS services.
  3. Inspect DHCP scopes and available IP addresses.
  4. Check DHCP relay and VLAN connectivity.
  5. Check DNS records and configurations.
  6. Restore services or saved settings if needed.
  7. Test IP address assignment on client computers.
  8. Test DNS resolution and access to the server.

Testing and Maintenance

  • Recovery plans should be reviewed regularly.
  • Backups should be tested to confirm they can be restored.
  • Recovery procedures should be tested after major network changes.
  • Staff should know their responsibilities during emergencies.
  • Recovery results should be recorded and reviewed.

Recovery time and acceptable data loss targets should be agreed with facility management before an actual disaster occurs.
